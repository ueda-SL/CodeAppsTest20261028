# Code Apps テスト管理 - 要件・実装トラッカー

## 目的

ワークスペース名 `CodeAppsTest20261028` から提案した「テストケース・実行・不具合管理」を、開発者向け Code Apps として構築する。これは業務資料に基づく確定要件ではなく、ユーザーが選んだクイックスタート範囲に対する仮説ベースの初期版である。

## 事実

- 作業フォルダーに業務資料はなかった。
- 対象の Power Platform 環境は Developer 環境であることをメタデータで確認した。
- Dataverse に既存のカスタムテーブルは多数あるが、同じ目的のテスト管理アプリは見つからなかった。
- 開発環境へのデプロイと動作テストが依頼範囲。認証キャッシュは別プロセス・別作業ディレクトリで検証済み。
- 環境 ID、URL、テナント情報などはルートの無視対象 `.env` にのみ保存する。

## 仮説

- 主な利用者は開発者と QA 担当者で、社内の Code Apps 開発テストを管理する。
- テストケース、実行結果、不具合を Dataverse で関連付ける。
- 初期版はこの環境の既存アクセス制御を使い、セキュリティロール変更や一般利用者への共有は行わない。
- 検証用のレコードは合成データに限定し、動作確認後に削除する。

## 提案する初期範囲

1. テストケースの登録・検索・編集・有効状態管理。
2. ビルド／環境を記録した実行結果の登録と、ケースへの関連付け。
3. 不具合の記録と実行結果への関連付け。
4. 合計・成功率・失敗数・ブロック数・未解決不具合数のダッシュボード。
5. AI は初期版では接続しない。将来、失敗ログ要約やテスト観点候補を人が確認する機能を、利用可能なライセンスと費用を確認してから検討する。

## 決定済み構成

- 既存 `mskk` Publisher を再利用し、専用 Solution `Code Apps Test Management` を作成した。
- Dataverse に Test Case、Test Execution、Defect の各テーブルと lookup relationship を作成した。
- 専用の Dataverse 接続と Solution connection reference を作成し、Code App に接続した。
- 環境 URL / ID、tenant 情報、接続設定は無視対象 `.env` に限定し、文書には記載しない。

## 完了条件

- 仕様・設計・受け入れテスト文書を実装内容に合わせて維持する。
- Code Apps の型チェック・lint・build・predeploy が成功する。
- Developer 環境にアプリと Dataverse 構成をデプロイする。
- ケース登録から実行結果・不具合の関連付けまで実動作を確認する。
- テスト用レコードを削除し、公開可能な範囲の検証結果を記録する。
- Publisher/Solution/スキーマの権限が不足する場合は、書き込みを止めて未完了として報告する。

## 実装済み範囲と確認状況

- テストケースは作成・検索・編集・有効／無効切り替え・確認付き削除に対応する。検索対象はケースキー、ケース名、領域。
- テスト実行はケース、ビルド、環境、状態、実行日時、実際の結果、メモを記録する。
- 不具合は実行とケースに関連付け、重大度と状態を管理する。
- Dashboard はケース数、実行数、成功率、失敗数、ブロック数、未解決不具合数と最近の実行を表示する。
- 作成・編集・削除、ケース／実行／不具合の関連付けを合成データで確認し、作成した検証レコードは削除済み。
- 最新 UI 変更を含む lint、build、predeploy と更新版 Code App のデプロイが成功した。
- デプロイ後、ローカル Power Apps player で Dashboard の集計カード、ケース検索、有効／無効保存を確認し、合成ケースを削除した。
- Dataverse の3テーブルがいずれも空であり、`Is Active` 列が Boolean 型であることを確認した。
