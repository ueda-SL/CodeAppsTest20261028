# テスト要件: Code Apps テスト管理

## ローカル品質検証

- TypeScript 型チェックと production build が成功する。
- ESLint が成功する。
- `npm run predeploy` が成功し、未登録ルート、プレースホルダー、CSP 危険パターンを検出しない。
- ケース検索のキー・名称・領域照合、有効状態の読み書き、状態集計を確認する。

## 受け入れテスト

| ID | シナリオ | 期待結果 |
|---|---|---|
| AT-01 | 必須項目を満たすテストケースを登録する | 一覧と詳細に保存値が表示される |
| AT-02 | ケースをキー・名称・領域のいずれかで検索する | 条件に合うケースだけ表示され、該当なしも区別される |
| AT-03 | ケースを指定し、ビルド・環境・Pass を記録する | 実行がケースに紐づいて一覧と集計へ反映される |
| AT-04 | Fail 実行から不具合を登録する | 不具合が実行と関連し、Open 件数が更新される |
| AT-05 | 不具合を Resolved に更新する | 未解決不具合集計から除外される |
| AT-06 | 必須値を省略して登録する | 保存せず、該当入力欄に説明を表示する |
| AT-07 | Dataverse 接続や権限が不足した状態を確認する | 成功表示や偽データで置き換えず、エラーを表示する |
| AT-08 | Developer 環境で一時ケース・実行・不具合を作成する | 読み戻しと関係を確認後、テストデータを削除する |
| AT-09 | ケースを無効にして保存する | 一覧と編集画面で無効状態が保持される |
| AT-10 | Dashboard を開く | ケース数、実行数、成功率、失敗数、ブロック数、未解決不具合数と最近の実行が表示される |

## 実施済み確認

- lint、TypeScript を含む production build、predeploy が成功した（最新の UI 変更を含む）。
- Power Apps 上でケース、実行、不具合の作成・更新・削除と関連付けを合成データで確認した。
- Dataverse API でも3テーブルの CRUD と lookup を確認し、検証レコードを削除した。
- 不具合編集画面の実行状態表示が、実行状態の日本語ラベルを使うことをローカルで確認した。
- 最新版を Developer 環境へ再デプロイし、ローカル Power Apps player で Dashboard の追加集計カード、検索、無効状態の保存・一覧表示を確認した。
- 合成ケースを削除後、Dataverse の3テーブルがいずれも0件であること、および有効状態列が Boolean 型であることを確認した。

## デプロイ後確認

- 初回 push が承認済み Solution に登録され、対象環境が Developer 環境である。
- 公開された URL を開き、画面遷移、Dataverse 接続、CRUD、集計を確認する。
- 一時テストデータを削除し、作成した記録が残っていないことを確認する。
- URL と結果は公開可能な範囲に限って記録し、認証情報・tenant ID・環境 ID は文書へ複写しない。
